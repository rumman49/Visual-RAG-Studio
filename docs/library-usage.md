### Retrieval metric display correction (2026-10-27)

Chroma is configured with cosine distance. That raw value is a vector-search distance (lower means closer), not a relevance probability or confidence score. The previous RRF/weighted fusion code overwrote it with `1 - normalized fusion score`; a document ranked first in both RRF branches therefore displayed `0.0000` under a misleading “Chroma distance” label. BM25 also emitted a made-up reciprocal score as a `distance`. Fusion now preserves the actual dense cosine distance, exposes RRF/weighted/BM25 scores as separate fields, and leaves distance absent for sparse-only results. The playground labels these metrics by their meaning; RagSpark Flash does not currently expose a reranking confidence score.

### Story 6 storage and trace ownership (2026-10-26)

No new third-party runtime library was added for persistence exploration or query traces. Storage and provenance remain product-owned across the existing SQLAlchemy/SQLite metadata adapter, Chroma `PersistentClient`, managed upload directory, and deterministic RAG runner. SQLite stores document records and effective chunking settings; Chroma stores vectors plus chunk text/metadata; source bytes stay in the managed local directory. The storage and chunk explorer APIs expose bounded, paginated metadata/text rather than arbitrary database access. Query execution traces are returned to the requesting UI with retrieved source text, Chroma distance, context preview, provider output/status and timings; query/answer traces are not persisted. External generation still requires explicit per-query consent. This is a local-development design, not a multi-user production storage boundary.
